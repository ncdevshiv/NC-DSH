<a id="adr-1"></a>
## ADR 1 —— 平台自有存储

**决策。** NC-AG 拥有自己的 SQLite 数据库，而不是扩展 harness 会话日志。

**原因。** 平台运行许多并非 harness `Agent` 值的智能体，它们的任务、消息、租约与决策必须在 harness 重启后存活，且不得触碰会话格式。独立数据库还使平台可以嵌入任何宿主进程，包括独立运维工具。

**放弃。** 平台不会出现在 harness 会话列表中，也不使用 harness 回放。它以自有事件流与审计链替代。

<a id="adr-2"></a>
## ADR 2 —— 隔离工作树、租约与围栏

**决策。** 每个智能体在自己的 Git 工作树内写入，受路径租约保护，租约携带单调围栏令牌，变更经集成管理器落地。

**原因。** 两个智能体编辑同一目录会在提交边界之间丢失工作，且共享树无法按智能体回滚。带围栏令牌的租约还会拒绝仍持有已过期租约的慢速智能体，这是单纯时间戳检查做不到的。

**放弃。** 每个任务更多设置（一个工作树与一个分支），以及共享目录本不需要的集成工作。平台接受该成本，因为丢失智能体工作更糟。

<a id="adr-3"></a>
## ADR 3 —— 基于证据的完成

**决策。** 只有当每个验收标准都有已执行检查记录的通过证据时，任务才完成。智能体报告永远不是证据。

**原因。** 智能体声称成功并不证明成功，干净合并也不证明集成正确。保存命令、退出码与输出使该主张可被后来的读者核查。

**放弃。** 完成需要为每种验证方法配置检查，未配置检查的部署无法完成此类任务。平台把它报告为失败，而不是静默通过。

<a id="adr-4"></a>
## ADR 4 —— 模型层级而非按档案指定模型

**决策。** 档案声明能力层级；路由使用部署偏好与选择策略把层级解析为具体且已定价的路由。

**原因。** 按档案指定模型标识会让每个档案成为部署工件，并在提供方重命名模型时失效。层级让一份配置驱动整个组织，并为例行工作保留最便宜的可用路由。

**放弃。** 部署不能在不为其单独定价的情况下把档案固定到某一确切模型。这是有意为之：未定价的路由会被拒绝，因此固定模型是显式、已计价的选择。

<a id="adr-5"></a>
## ADR 5 —— 默认确定性规划

**决策。** 请求分析、需求规范化与任务图构建通过确定性分析器运行。模型辅助规划不是默认路径。

**原因。** 规划发生在任何智能体存在之前，因此此处的模型调用会是无主、无路由、无审查的未核算工作。确定性分析器产出与模型规划将被校验成的相同记录类型，因此两条路径日后可互换而无需改动任何下游模块。

**放弃。** 基于关键词与语句结构构建的计划，比推理模型对模糊请求可能产出的计划更简单。平台通过记录每处歧义、并在歧义重大时提出决策来补偿。

<a id="adr-6"></a>
## ADR 6 —— 编排器决策，基础设施执行

**决策。** 编排器做出规划、调度、审查与决策选择。存储、运行时、Git 与租约管理器执行它们，执行模块不回身向编排器请求许可。

**原因。** 既做决策又机械执行自身决策的单一智能会成为单点故障：它重启或出现缺陷时执行也随之丢失。保持执行确定性意味着状态可存活，替代编排器可在同一执行层上恢复。

**放弃。** 某些操作比紧耦合实现多一步记录（决策加执行调用）。审计链是该成本的回报。
