# Agent Note: Durable workspace change summaries

Status: implemented

[English](2026-10-27-durable-workspace-change-summaries.md) | 中文

## Problem

改动文件卡片由记录该轮次的那次 Host 进程提供。Host 重启或冷挂载后，Session 日志中的 `workspace/changes` 宣告背后没有摘要，浏览器请求摘要路由得到 404，卡片便悄无声息地消失。用户看不到一个确实改动了文件的轮次应有的卡片，浏览器控制台只留下一条没有说明原因的 404。

## Decision

Host 把每份记录下来的摘要持久保存，存放在 `workspace_changes` 存储域中：每个 Session 一份文档，按宣告事件的序号保存该 Session 的各份摘要。文档携带文件列表、行数与工作目录。同一 Harness home 上的后来的 Host 会提供这份已存的摘要，因此重新打开的对话保留先前轮次的文件列表，其中所列文件的原生打开也随之可用。

对比不持久保存。它需要每个文件的两侧内容，也就是记录器临时目录里的快照对象与捕获副本；为它们另存一份会把工作区内容再放进 Harness home 一遍。因此由更早的 Host 记录的轮次会列出自己的文件，并说明对比已不可用。

`workspace/changes` 事件仍然只携带轮号。事件继续宣告某轮改动了文件，存储保存该宣告所指的文件列表。Session 日志会上传到 DeepSeek 的 session-log 服务，因此把文件列表放进事件会让工作区的每条路径离开本机。

客户端把 Host 的答复读作三种状态之一。Host 不提供的摘要，在卡片本该出现的位置留下一条说明文件列表不可用的提示；读取失败是另一种状态，在同一条提示旁提供重试；提供到的摘要照旧渲染卡片。

插件现在声明 `storageDomain` 服务，因此挂载它却没有存储栈的组合不会激活它。正式提供的 Web bundle 本就挂载了存储栈。

## Alternatives considered

**把文件列表放进 `workspace/changes` 事件**是最早的实现，在[历史本轮改动文件卡片决策](../../archived/feature/2026-09-11-turn-changed-files-card.md)中已被否决：卡片会永远从日志渲染，而它打开的内容却无法存活。session-log 的上传再次决定了这一点，因为日志中的每个事件都会发给 DeepSeek API。

**为快照建立 Harness home 下的对象库**在同一决策中被考虑并在那里否决；对比依然没有持久存储的归宿，摘要也不需要。

**保留进程内的摘要并解释这个 404**，仍然让用户拿不到一个确实改动了文件的轮次的文件列表，而这正是卡片存在的意义。提示是额外补上的，因为 Host 无法提供的摘要是一种用户应当看见的状态，而不是一张没有解释的空卡片。

**每个轮次一个存储域**会为每条宣告写一份文档。每个 Session 一份文档让文档数量与对话数量成正比，读取也只是一次查找。

## Consequences

Harness home 多出一个 `workspace_changes` 存储：存储根下每个 Session 一份 JSON 文档，保存该 Session 的各份摘要。插件从不删除这些文档；删除它们意味着删除该存储。

存下的摘要不含 git 的快照 id，因为它们指向的对象位于记录器的临时目录里，随之消失。因此从存储提供的摘要与实时摘要在这些 id 之外没有差别，而没有任何路由会提供它们。

对比仍然只属于当轮。重开的轮次显示自己的文件列表并说明对比不可用，review tab 也作同样说明。

针对性测试覆盖存储的写入与读取、由后来的 Host 在同一存储根上提供的摘要、不符合其模式的记录、打不开的存储、写不下的摘要、客户端的三种状态，以及它们渲染出的提示。
