# Agent Note: 工作区删除会话清理与未分组批量归档

Status: implemented

[English](2026-08-24-workspace-delete-session-cleanup-and-ungrouped-archive.md) | 中文

## 问题

删除 Workspace 注册记录时，仅从注册表中移除该工作区实体，而保留其已持久化的会话日志。由于侧边栏浏览器通过汇总各个存续工作区的记账会话，并将剩余未分配会话归入“未分组”（Ungrouped）桶，导致删除项目后其所有会话全部涌入未分组。想要清理或删除项目的用户不得不逐一手工归档大量松散会话。此外，未分组区段标题栏也没有提供一键批量清空或归档全部松散会话的操作菜单。

## 决策

1. **工作区删除对话框选项**：`WorkspaceBrowser` 中的工作区删除 Modal 现在包含一个勾选项（“同时归档此工作区的会话”，默认勾选）。确认后，客户端会自动对所删工作区包含的所有会话触发 `archiveSession`，防止它们散落到未分组视图中。
2. **未分组批量归档操作**：`ProjectRowItem` 与 `SessionTree` 现已支持在未分组标题栏显示操作菜单。当存在未分组会话时，标题栏显露操作菜单并提供“归档全部会话”，一键完成所有松散会话的归档。

## 验证

`packages/client/ui-workspace` 的单元测试固定了：
- 删除工作区时勾选/取消勾选会话归档选项的行为。
- 打开未分组分组菜单并批量归档所有未分组会话。
- 全量 typecheck 与组件测试覆盖。

## 已考虑的替代方案

**删除工作区时直接删除其会话。** 否决：移除工作区刻意保留已持久化的会话日志；归档在清理浏览器视图的同时把每份日志都留在磁盘上。

**确认后无条件归档。** 否决，改为显式、默认勾选的选项：批量状态变更保持在删除对话框中可见，想要纯注册删除的用户可在同一操作中取消勾选。

## 后果

删除项目后其会话不再涌入未分组；一旦未分组会话累积，其标题栏也提供一键批量归档。归档经由与手工归档相同的客户端 `archiveSession` 路径完成，因此可按会话撤销；代价是破坏性对话框内多了一个默认勾选的批量动作，用户需要注意到它才能拒绝。
